# Rust Web 最终阶段验收

以下汇总此前真实双账号测试及本地记录，不把离线 CI 当作真实平台验收。
公开记录省略群名、成员标识、消息正文、凭据及本地数据库。9 月 16 日文档是历史快照。

## 已验证

| 范围 | 结果与证据边界 |
| --- | --- |
| 登录与连接 | 全新 Rust 登录、续期、NIM 认证/心跳、重连和重启会话恢复 |
| 消息 | 双账号独立收发、服务端确认、对端解码入库、ACK 刷出与重启去重 |
| 普通成员 | 文本发送可用；管理操作仍校验管理权限 |
| AI | 明确提及回复、普通聊天静默、上下文、当前群知识与资料缺口、管理员摘要 |
| 公告 | 创建、编辑、对端读取、删除和恢复；回读确认内容 |
| 禁言 | HTTP 与 NIM 写入、禁言名单回读、被禁成员发送遭拒；解禁后发送成功 |
| 撤回 | 精确消息绑定、服务端接受、另一个账号独立收到撤回通知 |

`sent` 或 `server-accepted` 不是对端收到的同义词；`flushed` 不是用户已读。
未知回执保持 `unknown`，不自动重发。撤回不删除管理员审计历史。

## 单群并发与超时对照

同群五条同时提交后按群顺序处理，不是五个并行模型请求。初次样本 4/5 成功，
一次 15 秒超时。后续 A/B 对照各五条：15 秒上限组 5/5，40 秒上限组 5/5，
AI 运行耗时分别 3.01–4.00 秒、2.66–8.52 秒；每条一次回复，无串号或重复。
完成后观察窗口为 10 秒，不代表长期去重保证。

两组均未越过 15 秒，未复现故障，因此不足以认定上游根因或证明提高上限有效。
已恢复 15 秒请求上限、20 秒链路预算及原测试群开关。模型配置未更换。
