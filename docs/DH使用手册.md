# DH BOT 3.0 Beta 1 大白话使用手册

## 一、DH BOT 是做什么的

DH 借用已经登录的旺商聊账号收发群消息，主要做四件事：

1. 看群消息，按规则撤回、禁言、移出或提示。
2. 用 AI 回答群里的问题，并结合群规、FAQ 和文档回答。
3. 记录任务，到期后在群里提醒。
4. 保存消息、自动动作和审计，方便管理员回头查。

DH BOT 3.0 使用 Rust + Tauri 桌面窗口。正常使用只运行 `DH-BOT.exe`，旺商聊协议桥、SQLite 和后台任务都在主程序里。
生产包固定连接真实旺商聊 `127.0.0.1:9222`，开发测试工具不会放进生产包。

### 3.0 运行维护

- DH 是单实例程序，再次双击会显示当前窗口。
- SQLite 已编进主程序，WebView2 由安装包离线携带；日常使用不用安装 Go、Rust、.NET 或 Java。
- 3.0 数据库位于 `%APPDATA%\\DH\\3.0\\dh.db`，迁移前快照位于其 `backups` 目录，最近保留三份。
- 异常诊断日志位于 `%APPDATA%\\DH\\3.0\\logs`，密钥、Token 和 Cookie 会自动脱敏。
- Windows Explorer 重启后，DH 会自动重新注册通知区图标。
- Windows 设置页可保存旺商聊程序路径并自动启动。已有旺商聊但没有 9222 时，DH 会先询问；确认后才结束精确匹配的旺商聊进程并重启。

## 二、DH BOT 怎么认群和成员

这部分很重要。

- 一个群看 `groupId`。群名改了，`groupId` 还是原来的值。
- 一个人优先看 `userId`。旺商聊成员明细缺失时，DH 还能用 `nimId` 保持身份并完成群名片操作。
- 旺商号、昵称和群名片主要用来显示，不作为数据库主键。
- `groupCloudId` 是旺商聊内部 NIM 群标识。DH 发消息或撤回时自动做映射，界面里
  仍然统一显示 `groupId`。
- Windows 和 macOS 旺商聊使用同一套消息与群管理数据结构。DevTools 和本地桥端口
  可以配置，DH 还负责消息解码、序号确认、群映射和动作校验，所以并非只替换端口。

DH 不把“大海兼职群”或任何群号写死。连接成功后从“群组与成员”列表里选群。

## 三、运行前准备

### 旺商聊登录状态保存

旺商聊原版本每次启动会生成新的 Electron 登录分区，DH BOT 3.0 会在首次使用时把它切换为固定的 `dh-primary` 分区。

第一次应用时可能出现一次 Windows 管理员确认，这是为了备份并更新旺商聊启动脚本；DH 不保存旺商聊密码。若当前旺商聊刚刚登录成功，DH 会优先迁移最近的登录分区；否则在固定分区登录一次即可。之后关闭并重新打开 DH，会继续使用原账号会话。

设置页的“恢复原文件”只恢复旺商聊启动脚本，保留旺商聊自己的账号数据。旺商聊升级后如果状态显示“更新后待重新应用”，重新点击“启动 / 重启旺商聊”即可。

### Windows 旺商聊

1. 安装旺商聊。
2. 双击 `DH-BOT.exe`。DH 会定位旺商聊并用下面的参数启动：

```text
--remote-debugging-port=9222 --remote-allow-origins=http://127.0.0.1:9222
```

3. 旺商聊窗口会恢复到前台；第一次完成登录后，后续启动复用固定登录分区。

也可以先设置旺商聊路径，然后双击 `Start-DH.vbs`。它以隐藏方式启动，不保留 CMD 黑窗口：

```bat
set "WSL_EXE=C:\Path\To\WangShangLiao.exe"
Start-DH.vbs
```

### macOS 旺商聊加 CrossOver

macOS 旺商聊可以提供登录会话，DH-BOT.exe 放在 CrossOver 里运行：

```sh
open -na '/Applications/旺商聊.app' --args --remote-debugging-port=9222
```

DH 设置页保持：

```text
旺商聊 DevTools  http://127.0.0.1:9222
内嵌桥地址       http://127.0.0.1:51235
```

CrossOver 与 macOS 共用本机回环网络时，这套地址可以直接连接。

## 四、第一次启动

1. 旺商聊先登录，再打开 DH。
2. 看右上角状态。显示“已连接”后，进入“群组与成员”。
3. 点“同步群”。
4. 在群列表点中要管理的群，核对群名，并确认当前账号已经被设置为群主或管理员。
5. 点“启用 / 停用”，让这一行状态变成“是”。
6. 填欢迎语。开启自动群名片后，新成员先完成改名验证，再把 `[成员]` 替换成新群名片，例如 `@[成员]` 显示成 `@「广校」`。手工建立初始成员基线时不发送欢迎。
7. 需要每日摘要时勾选本机时间选择器并选择时间；摘要只保存在 DH 总览，不发送到群里。
8. 先在测试群发几条消息，去“审计”查看命中和动作。

新同步的群默认处于停用状态。只有明确启用的群进入消息处理流程。DH 只建立一套 ZCG 兼容全局规则，所有已启用群共同继承。当前账号不是群主或管理员时，操作区提示
“需要将账号权限设置为管理”。

## 五、九个页面怎么用

### 1. 总览

这里看旺商聊、AI、启用群数量、已处理消息和自动动作。

- 每日摘要：显示 AI 对各群最近消息的私密总结。选中后点“查看所选摘要”可阅读完整内容，数据只保存在本机数据库。

- “暂停全部自动化”：继续收消息和落库，但暂时跳过在线入群自动改名、欢迎、规则、AI 和定时任务。管理员明确点出的“一键执行”仍会处理队列。
- “恢复全部自动化”：新收到的消息继续按群配置处理。
- 最近自动动作表：看撤回、禁言、移出、改名片和手工操作是否成功。

### 2. 群组与成员

页面分成左右两个 TAB：“群组”和“成员”。先在“群组”TAB 点中目标群，再切到“成员”TAB查看成员和群名片工具；切入时 DH 自动生成该群建议名称，“生成建议”按钮可再次刷新。两个 TAB 分别保存搜索词和页码。

- 同步群：刷新群列表，并重新读取当前选中群的成员明细。这个动作只同步数据，不发送欢迎。
- 启用 / 停用：控制这个群是否进入处理流程。
- AI 开关：控制这个群的 AI 问答。
- 规则开关：控制这个群的群管规则。
- 人工接管：打开后暂停这个群的 AI 自动回复，确定性群管规则继续运行。列表中的
  “AI 自动回复”就是关闭人工接管后的状态。
- 任务提醒：控制这个群是否发送到期任务提醒。
- 保存群设置：保存欢迎语和每日摘要时间。
- 全员禁言 / 解除全禁：直接调用旺商聊群管理能力。

成员表按 `userId` 保存，首列是数字序号并带多选复选框，角色原始字段不会显示在前台。成员标题直接显示本次同步人数。
点成员后，可填写 1 到 43200 分钟的禁言时长，再执行禁言、解禁或移出。
群主和管理员在默认规则里有角色豁免。

“清理封禁成员”会先刷新当前群成员，再按旺商聊原始 `accountState` 识别注销和封禁状态，并兼容群名片或昵称恰好为“该用户已注销”“已封禁用户”的普通成员。即使注销账号仍保留旧昵称，DH 也会在前台显示“该用户已注销”。界面先显示命中人数并要求确认，确认后逐个移出，成功和失败都写入审计。群主、管理员、当前登录账号和系统账号不会进入候选。这两类失效账号不进入一键改名和自动改名。

“恢复所有群员名称”会把 DH 管理过的普通成员恢复为首次保存的原名称。勾选成员后按钮变成“恢复该群员名称（数量）”，只处理勾选项。执行前会显示人数并要求确认。

ZCG 的 `QX_Group_GetUserList` 与旺商聊 `get-group-members` 使用同一成员名单来源，因此也只会拿到接口当次返回的成员。旺商聊显示的群总人数大于接口名单时，那部分未返回成员的群名片 ZCG 同样拿不到。DH 额外合并 NIM 名单、入群事件和发言身份来持续补齐，并在标题显示“群人数 / 已识别 / 缺口”，但未出现在任何来源里的成员仍计入覆盖缺口。

#### 群名片怎么用

1. 选中群，先点“预览”。有正常名称的成员会生成两字简称：两字保持原样，三字取首尾，四字及以上从前后两段各取首字，例如“广州校长”变成“广校”。
2. 两个人简称相同时，DH 继续尝试原名里的其他两字组合。仍然重名，或名称为空、`1`、`.`、纯数字时，进入固定编号。
3. 默认编号从 `DH群员0001` 开始。后缀固定四位且只读，顺序为 `0001–9999`、`a001–z999`、`aa01–zz99`、`aaa1–zzz9`，每个群共 261081 个。成员退出后，原编号继续保留。
4. 需要调整正常成员的两字简称时，选中成员，在底部修改建议；固定编号前缀统一在“设置”页面调整。
5. 核对成员表里的原名、建议名、后缀、来源和状态，再点“一键执行”。群主、管理员、当前账号和系统账号会列为角色排除。这个按钮是管理员明确发起的任务，即使总览处于“暂停全部自动化”也会继续执行。
6. “自动：开”后，在线新成员自动改名；DH 停机期间加入且下次启动仍在群里的成员，会显示为“离线新增”并自动补改。
7. “新增N”保留到管理员点击查看；失败任务点“重试失败”。成员 TAB 的“暂停”会暂停这个群的全部群名片队列，包含一键任务。

未获得名称的前缀默认是 `DH`。前缀入口位于“设置”，作用于当前选中群。把前缀改成其他文字且已经有编号成员时，界面提示：
“原本使用「DH」前缀的已改用户是否一同更改？”按钮只有“确认”和“保留”。“确认”保留每人的四位后缀并批量换前缀；“保留”让旧成员保持原名称，新前缀从后续成员开始使用。

成员标题显示群人数、已识别数、覆盖缺口、待备注和失败数。覆盖有缺口时，一键操作先处理已识别成员；后续成员快照、NIM 入群事件或成员发言会继续补齐。成员在 DH 停机期间加入后又退出时，不进入当前在群任务。

旺商聊新版界面虽然移除了成员禁言入口，当前协议仍保留
`/v1/group/set-member-mute` 和 `/v1/group/member-mute-cancel`。DH 直接调用这两个群管理
接口，禁言请求中的 `min` 就是分钟数。

### 3. 消息台

上半部分按群名称下拉，可多选后一次向多个群发送人工消息。下半部分只显示所选群的
最近消息，类型统一显示为“文本”“图片”“名片”“其他”。DH 只处理群聊文本，
图片目前只识别“这是一条图片消息”，不分析图片画面。

消息流水线顺序是：读取、写 SQLite、确认旺商聊源队列、按群串行处理。唯一键由账号、群 ID 和服务器消息
ID 组成，重复推送只保存一次。

### 4. 规则

最简单的加词方法：

1. 进入“规则”，选择一个当前账号具有管理权限的群用于权限校验。
2. 关键词填需要检测的文字。
3. 默认只勾选“撤回”；确实需要时才手动勾选“禁言”。
4. 点“添加规则”。

简单添加默认使用“包含”匹配，群主和管理员豁免，并保存为全局规则。首次升级时，DH 会把各群中的旧内置模板合并成一套 `ZCG-Compatible-Rules.json` 全局模板；其他自定义群规则保留为群级补充规则。

复杂规则使用 JSON 导入。支持：

- `exact`：完全一样
- `contains`：包含文字
- `prefix`：以某段文字开头
- `regex`：正则表达式
- `length`：加权字符数
- `lines`：行数
- `image_count`：时间窗内图片次数
- `rename_count`：改名片次数
- `blacklist`：黑名单
- `semantic`：AI 语义分类

模式有三种：

- `auto`：命中后执行动作
- `observe`：只记审计
- `dry-run`：用于规则测试

多条规则同时命中时，DH 合并动作。强度是移出高于禁言，禁言高于回复。执行顺序是：
撤回、移出或禁言、加入黑名单、提示、写审计。

### 5. 知识与 AI

知识库支持一个库绑定多个群、一个群使用多个库。先在页面顶部选择知识库，再保存 FAQ 或导入 UTF-8 的 `.txt` / `.md` 文件；群选择用于绑定和解除绑定。

新安装从空知识库开始，不自动绑定任何群。没有绑定群时，AI 不会使用该库；需要保守模板时可新建知识库后导入管理员确认过的群规与 FAQ。

文档会按段落和长度分块，用本地中文关键词与字符 n-gram 检索。每个群只检索自己的
知识，`groupId=0` 的内容可作为公共知识。

### 6. 任务与摘要

创建任务时先选择一个群，再填写：

- 任务标题
- 负责人内部 `userId`
- 到期时间，例如 `2026-07-20 18:30`

到期后 DH 按负责人 `userId` 找到其最新群名片，用 `@名称` 在群里提醒一次，并记录提醒
时间。点任务行后再点“完成所选”即可结束任务。
这就是旧界面里“发布任务”的用途：先把待办保存到 DH，到期再提醒；创建时本身不会立即在群里发一条任务公告。

“生成群摘要”会读取最近最多 500 条消息，交给当前 AI，然后写入总览的“每日摘要”。结果不发送到群里。每日摘要使用 Windows 原生本机时间选择器设置，同一个群每天执行一次；未勾选时间表示关闭。

“每日群发言计划”用于按电脑当前时区自动开群和关群。先选择一个或多个群，再设置计划名称、开群时间、关群时间并勾选“启用计划”。开群允许全员发言，关群执行全员禁言；DH BOT 仍继续接收消息和记录审计。计划支持跨午夜，程序重启后会按当前时段立即校正。一个群只能属于一条启用计划，转移到其他计划前会弹窗确认。

### 7. 审计

这里记录连接、群同步、欢迎语、规则、AI 决策、任务提醒、摘要和协议动作。可按群名称
多选筛选；事件、动作、级别和 DH 生成的详情都显示中文。出现问题时先按时间看最后几行，再核对成员和详情。

### 8. 设置

默认连接：

```text
旺商聊 DevTools  http://127.0.0.1:9222
内嵌桥地址       http://127.0.0.1:51235
```

AI 有两种接法：

1. `openai`：填写 OpenAI-compatible Base URL、模型和 API Key。
2. `webhook`：AI 类型填 `webhook`，再填 Webhook URL。

当前发行版的 OpenAI-compatible 默认值是：

```text
Base URL  留空
模型      deepseek-v4-pro
```

API Key 仍由使用者在实际 Windows/CrossOver 环境保存，Windows 会用 DPAPI 生成当前用户专属密文。

点“保存设置”后配置立即生效。“测试连接”检查旺商聊。“测试 AI”会打开独立对话窗口，显示完整回复、理由、置信度、模型和耗时。最近 10 轮只留在窗口内存中，点“清空对话”立即清除。该测试不读取群消息、不发送群消息；模型返回的动作和任务只展示，不进入协议层。

### 9. 调试

这里集中看 DevTools、NIM 账号、当前协议页面、数据库 schema 和固定登录分区维护状态。连接问题先点“立即检查”；显示 `nim-not-ready` 时，把旺商聊窗口调到前台完成登录并等待会话初始化。

群公告能力当前显示“功能未开放”。程序不会在协议能力未确认时模拟保存成功。

## 六、ZCG 兼容规则模板

### 作用范围和动作

模板导入后保存为 `groupId=0` 的全局规则。新安装不会自动启用模板；管理员导入并明确启用后，默认动作只撤回对应消息，不执行禁言、移出或拉黑。自定义规则仍可手动选择其他动作。

### 字符怎么数

- 一个汉字算 2。
- 字母、数字、符号和其他 Unicode 字符算 1。
- 加权字符超过 100：撤回。
- 加权字符超过 200：撤回。

这里的“超过”是严格大于。刚好 100 或 200 不触发对应阈值。

### 其他默认项

- 超过 4 行：撤回。
- 图片消息：撤回。
- 同一成员 10 分钟内第 3 张图片：撤回。
- 改群名片、累计改名和黑名单检测：对应规则保留命中记录，默认动作只撤回。
- 群主、管理员默认豁免。

AI 广告、辱骂、诈骗规则默认是 `observe`。确认识别效果后，可以在导出的 JSON 中把单条规则改成 `auto`；动作仍只撤回。

DH 第一次同步成员时保存原名。一键规范验证成功后，锁名片基准切换为新的简称或固定编号；
以后检测到成员自行改名，会恢复这个已规范名称并发送名称提示。身份依据是 `userId` 或已映射的
`nimId`，所以显示名称变化后仍能找到同一个人。

发行包的 `ZCG-Compatible-Rules.json` 可以直接导入。导入后统一保存为 `groupId=0` 的全局规则。

## 七、AI 什么时候回复

群聊回复只有一种触发方式：消息里明确出现 `@DH`。普通问句、单独出现 `DH`、昵称或旧版唤醒词都不会触发回复。AI 可以自然寒暄，但会把话题控制在当前群绑定知识库、群规、FAQ、任务和管理员配置范围内；人格细则见发行包中的 `AGENTS.md`。

预测同样只由明确提及触发：`@DH 预测` 会先列出当前可识别彩种，`@DH 预测 彩种名称` 会读取实时结果并在本地计算近期窗口、冷热、遗漏和候选方向。群回复只显示彩种、期号、最新结果、更新时间、趋势摘要、候选方向和参考度，不显示数据接口、供应方或原始响应结构。AI 服务暂时异常时，DH BOT 直接发送本地统计模板；数据链异常时明确说明暂不可用，不补造结果。

群内普通陈述可以送 AI 做广告、辱骂、诈骗等分类，但 AI 返回的回复字段会被忽略。
人工接管打开后，回复字段同样被忽略；已经启用的群管规则仍按模式运行。

## 八、Webhook v1

DH 发出 `X-DH-Contract-Version: 1`，请求包含群、成员、消息、最近上下文和检索到的知识。

响应顶层只接受：

```json
{
  "reply": "群规里的答案",
  "actions": [
    {
      "type": "ignore",
      "category": "scam",
      "groupId": 123,
      "confidence": 0.96,
      "reason": "疑似诈骗话术"
    }
  ],
  "tasks": [
    {
      "title": "跟进成员问题",
      "assigneeId": 456,
      "dueAt": 1784543400000,
      "description": "核对资料"
    }
  ],
  "confidence": 0.96,
  "reason": "命中群规和知识"
}
```

动作类型接受 `recall`、`mute`、`unmute`、`remove`、`rename`、`blacklist` 和 `ignore`。
DH 会校验群 ID、成员 ID、消息 ID、禁言分钟数、昵称、置信度和 JSON 字段。语义动作是否
进入协议层，最终由该群对应的 `semantic` 规则模式和阈值决定。

## 九、数据、密钥和备份

```text
%APPDATA%\DH\3.0\dh.db
%APPDATA%\DH\3.0\secrets.dat
```

- `dh.db` 保存群、成员、消息、私密摘要、规则、知识、任务、动作、审计和设置。
- `secrets.dat` 保存 DPAPI 密文，日志只写密钥引用。
- 消息默认保留 30 天。
- 审计默认保留 180 天。

备份时先退出 DH，再复制整个 `%APPDATA%\DH\3.0` 文件夹。这样数据库主文件、WAL 和密钥
引用保持一致。

3.0 不迁移 Go 版测试群、成员、规则、知识、任务和审计；旧文件会先归档到
`%APPDATA%\\DH\\legacy-backups\\<timestamp>`，旺商聊自己的登录分区不受影响。

## 十、常见情况

### 私信用户怎么处理

旺商聊私信是 `MSG_KIND_P2P`。发送者用消息里的 `from.id` 识别，也就是对方的 `userId`；
接收者 `to.id` 是当前登录账号。DH BOT 3.0 当前只管理群聊，监听到私信后会确认该消息，
但不写群消息库、不触发群规则、不交给 AI，也不会自动回复。私信不会混进任何群的审计。

### 一直显示等待旺商聊

核对旺商聊是否登录，以及启动参数里是否有 `--remote-debugging-port=9222`。浏览器打开
`http://127.0.0.1:9222/json/list` 时应看到旺商聊页面信息。

### 已连接但群列表为空

点一次“同步群”，再看审计。当前账号需要已经加入至少一个群，旺商聊页面也要处于登录
完成状态。

### 规则命中但动作失败

常见原因是当前旺商聊账号在该群缺少对应管理权限，或消息已超过旺商聊允许撤回的时间。
审计详情会保留协议业务错误。

### AI 状态显示未配置

OpenAI-compatible 模式需要填写 Base URL 和模型；Webhook 模式需要 URL。Base URL 填根地址时，DH 会自动补充 `/v1`。保存后点“测试 AI”，测试窗口不会读取或发送群消息。

### 成员改名后为什么还是同一个人

DH 优先按 `userId` 识别成员，HTTP 详情缺失时使用已映射的 `nimId`。群名片变化只更新显示名称和改名计数。

### 同步人数为什么和旺商聊群资料人数不同

旺商聊群列表有汇总人数，HTTP 成员明细有时只返回一部分。DH BOT 3.0 会再读取 NIM 群成员并按
`nimId` 合并，标题同时显示群人数、已识别数和覆盖缺口。部分名单不会触发本地成员删除；只有
完整名单才把缺席成员标记为离群。HTTP 名称为 `"1"`、`"."` 时，NIM 的真实群昵称会优先补上；
两个来源都缺少名称时显示“名称未设置”，并进入固定编号流程。

### 群公告在哪里编辑

当前真实旺商聊能力清单没有确认群公告写入路由，DH BOT 3.0 显示“功能未开放”，不会模拟保存成功；当前发行版覆盖欢迎、规则、AI、任务、成员动作和全员禁言。

### 搜索和翻页

页面顶部输入文字即可过滤当前表格。翻页按钮显示“上一页”和“下一页”，旁边会列出当前页、总页数和总条数。成员列表每页 200 人，其他表格每页 50 条；数据库内的已识别成员不会因分页丢失。群、成员和任务的选择按数据库 ID 保持，筛选后仍对应原对象。

### 窗口大小和后台驻留

- 窗口拉宽或缩小时，搜索、翻页、表格和操作区会自动重排。
- 最小窗口尺寸是 `1180 x 760`，到达下限后 Windows 会停止继续缩小，避免文字和按钮重叠。
- 点最小化或右上角关闭时，DH 收进 Windows 右下角通知区并继续处理已启用群。
- 双击托盘图标恢复窗口。右键菜单提供“显示 DH BOT”、“暂停/恢复全部自动化”和“退出 DH BOT”。

### 运行时要另外装东西吗

正常使用只有一个 `DH-BOT.exe`。Rust 运行时、SQLite 驱动、旺商聊桥和程序图标都已
编进 EXE，不用安装 Go、.NET、Java、VC++ 运行库或数据库。Windows 安装包携带 WebView2；电脑上只需旺商聊，DH 会负责定位、启动和连接。

## 十一、推荐上线顺序

1. 先配置旺商聊连接。
2. 只启用一个测试群。
3. 检查默认规则和角色豁免。
4. 配置知识和 AI，先使用语义观察模式。
5. 测试欢迎语、关键词、图片、任务提醒和摘要。
6. 从审计确认动作顺序与权限。
7. 再逐个启用其他群。
