# Windows Codex 全量实机验收补充

本补充与 `WINDOWS-CODEX-PROMPT.md`、`WINDOWS-REAL-MACHINE-TEST.md` 一起执行。先完成环境、登录和只读检查，再进入真实群写操作。每一个写操作记录原状态、请求、回执、回读结果与恢复结果。

## 0. 哈希语义与当前生产测试对象

- 本文档自身的 SHA-256 仅用于确认测试说明传输完整；它不是 EXE、ZIP、MSI 或安装包的期望哈希，严禁以文档哈希检索生产二进制。
- 当前 Windows 源码快照对应 `d739a70cb4446a9eb37bde1a0c3b62a5165c0c6b`。开始全量实机验收前，先从该快照在 Windows 本机构建生产包，再把构建出的 EXE、portable ZIP、setup 和 `SHA256SUMS.txt` 复制到本轮隔离目录。
- 生产产物哈希由本轮构建完成后生成并写入 `HASHES.txt`；只有 EXE/ZIP/MSI 的实际文件哈希参与二进制校验。
- 已安装的旧 beta 产物只作为历史基线记录，不作为本轮构建失败、文档传输失败或协议测试失败的证据。
- 源码、构建输出、哈希清单和测试报告必须携带同一轮时间戳与来源 SHA；版本不一致时先报告差异，再继续只读检查。

## 1. 启动、双实例与登录暂停点

1. 读取 APP 安装路径、版本、当前 PID、命令行、用户数据目录和调试端口占用情况。
2. 启动两个独立 APP 实例：实例 A 使用 `9222` 和独立目录 `PROFILE_A`；实例 B 使用 `9223` 和独立目录 `PROFILE_B`。
3. 两个窗口均恢复到前台，记录 PID、窗口标题、端口和用户数据目录。
4. 到此暂停，等待用户完成两个实例的登录。凭据只在 APP 登录界面输入，测试报告仅记录“已登录”。
5. 用户确认后，等待会话初始化，读取 `/json/version`、`/json/list`、页面标题、CDP 页面 URL、NIM 状态、当前账号和群数量。
6. 分别重启 APP、DH BOT、Windows，验证 `dh-primary` 登录分区、账号状态和 9222/9223 连接复用。维护动作只影响目标 APP 主进程，验证 PID、路径和创建时间后执行。

## 2. 生产产物与安装边界

1. 对 EXE、portable ZIP、安装包、规则模板、Markdown/PDF 手册生成 SHA-256、文件大小、版本和签名状态清单。
2. 在新目录解压 portable ZIP，验证直接双击启动、WebView2 提示、无 CMD 黑窗口、单实例、任务栏图标、托盘图标、最小化和退出。
3. 检索产物及运行目录，确认生产包没有 Fixture、`DH-Fixture.exe`、`9233`、`51300`、测试数据库、源代码、PDB、Source Map、原始协议、真实标识、凭据或开发命令。
4. 验证设置、日志、数据库、诊断包、手册和校验和文件路径在 `%APPDATA%\\DH\\3.0` 边界内；开发目录和生产目录相互独立。

## 3. 协议与连接探测

1. 验证 DevTools 页面发现、CDP 连接、Electron `ipcRenderer/xclient`、NIM 方法、群消息监听、轮询、ACK 与页面重载重装。
2. 读取能力矩阵：群列表、成员列表、成员详情、发送、撤回、成员禁言/解禁、改名、移出、全群禁言/解除、公告、成员事件。
3. 记录能力来源、协议指纹、状态、首次检测时间、错误类别和自动化开关；路由或响应结构变化时，准确显示对应能力状态，不把权限失败当作协议失效。
4. 模拟或实测 NIM 未初始化、NIM 503、CDP 断线、端口被占用、旺商聊重启、窗口隐藏到托盘和网络临时错误，检查 5 秒重连和中文诊断。
5. 相同群列表/成员列表请求验证 single-flight；群列表缓存 10 秒、成员缓存 30 秒；写入后的验证读取绕过缓存。

## 4. 账号、权限、群和成员读取

1. 验证当前账号信息、群主/管理员/普通成员身份，以及非管理员时写操作的中文禁用说明。
2. 验证群列表搜索、总数、分页、离线缓存、群名称多选、批量选择仅覆盖当前搜索结果。
3. 用 16、50、51、1000 成员场景验证 HTTP 分页、NIM roster、部分名单、完整名单和覆盖率。
4. 验证 `userId`、`nimId`、原名称、当前名片、DH 目标名片、角色、账号状态、加入来源、最后出现时间、黑名单、离群/再加入的身份收敛。
5. 验证数值字段、空字段、`.`、`1`、纯符号和已注销/封禁成员不会被误当作名称。
6. 完整名单才标记离群；部分名单保留历史成员。未知成员发言时补建身份并进入对应队列。

## 5. 消息流水线与可靠性

1. 验证文本、图片、名片、通知、其他、解码失败、本人消息、出站回显、P2P 消息和群通知的分类。
2. 固定检查顺序：接收 -> SQLite 入站落库 -> 连续 ACK -> 按群串行处理 -> 副作用 outbox -> 回执归档。
3. 验证重复、乱序、101 条分批、1000 条突发、监听重装、队列溢出、重启恢复和群映射延后到达。
4. 每个稳定消息 ID 只处理一次；相同动作 dedupe key 只执行一次；未知回执进入人工确认，不盲目重复写入。
5. 消息台验证搜索、群名称多选、类型、状态、游标分页、单条撤回、批量发送、逐群结果和失败重试。

## 6. 人工群控与批量群控

真实写操作只在已选择的测试群执行；保存原状态并在结束后立即恢复。

1. 发送唯一文本，验证 NIM 返回消息 ID 和出站回显。
2. 使用普通成员实例发送唯一违规文本，验证 `nim.recallMsg`、撤回通知、历史回读和客户端界面消失。HTTP `1001` 归档为永久失败，不进入退避重试。
3. 验证成员禁言、指定时长、解禁、状态回读。
4. 验证全群禁言、解除全禁和群发言状态回读。
5. 验证单成员改名、回读、恢复原名；验证一键规范、前缀变更、冲突排序、固定编号、失败重试和重启续跑。
6. 验证注销/封禁成员筛选、清理、黑名单加入/移除、重新入群自动处理和中文审计。
7. 验证批量公告、批量全员禁言、批量解除全禁：全选当前搜索结果、部分失败、逐群回执、失败重试和未知回执人工确认。
8. 真实群不执行移出成员；移出、黑名单重新入群移出和高失败率场景放在开发 Fixture。

## 7. 群公告、置顶和历史

1. 读取历史公告、作者、发布时间、已读数、置顶状态和当前内容。
2. 发布唯一公告，回读公告列表和群内公告通知。
3. 以作者身份编辑公告；验证内容更新、历史、置顶和取消置顶。
4. 验证 AI 优化仅修改草稿；发布操作必须由人工点击确认。
5. 恢复原公告内容和原置顶状态。审计写入公告标题摘要、操作类型、公告 ID、协议回执、回读和恢复结果。

## 7.1 固定双群批量验收

批量测试范围固定为 `TARGET_GROUP_A` 与 `TARGET_GROUP_B` 两个已指定测试群。开始批量模式前，先列出选中的群 ID、群名称和成员数；所选数量必须等于 2，且两个稳定群 ID 与目标清单逐项一致。

1. 验证群列表搜索后“全选当前搜索结果”只选择这两个目标群；筛选变化、切换批量模式、取消批量都会清空旧选择。
2. 批量公告：读取两群原公告和置顶状态，使用同一条唯一标记公告发布到两群；逐群回读公告历史、内容、公告通知、作者、消息 ID 和回执；随后恢复两群原公告与置顶状态。
3. 批量全员禁言：保存两群原群发言状态，按固定顺序执行 `TARGET_GROUP_A` 再 `TARGET_GROUP_B`；逐群回读禁言状态，并用普通成员实例验证两群发言状态。
4. 批量解除全禁：按固定顺序解除两群全群禁言；逐群回读允许发言状态，并用普通成员实例验证恢复结果。
5. 验证每群独立权限检查、能力检查、请求 ID、业务码、协议回执、动作记录和中文审计。单群失败时后续群继续执行，结果明确显示成功、失败或待人工确认。
6. 批量操作间隔至少 500ms；不确定回执不自动重试。失败群只通过“重试失败群”重新提交，保持原选择顺序。
7. 验证批量公告的 AI 优化只更新草稿；发布按钮显示准确的“发布到 2 个群”。
8. 批量操作结束后复查两群公告、置顶、群发言状态和普通成员实际发言结果均已恢复；其余群的公告、禁言状态、审计和动作数量保持不变。
9. 批量验收报告对每一项列出目标群、开始状态、执行顺序、完成状态、恢复状态、消息/公告/动作 ID、耗时和错误详情。

## 8. 机器规则与 AI 控制规则

1. 验证两个独立 TAB、独立群级开关、独立权限、独立审计与独立运行状态。
2. 机器规则覆盖精确、包含、前缀、正则、加权字符 100/200、五行消息、图片、十分钟三图、黑名单、名片修改、名片累计五次。
3. 机器规则命中后立即执行，连续刷屏逐条处理；只保留账户级 500ms 写入间隔。
4. AI 规则覆盖广告、辱骂、诈骗；一次 AI 请求统一判断启用规则；观察和自动模式分别验证。
5. 验证全局规则、多个指定群、搜索式白名单选择器、名称/原名称/DH 名称/userId/nimId 搜索、多选、优先级低中高和同级动作合并。
6. AI 超时、429、5xx、无效响应、置信度不足时不阻塞消息接收，不生成猜测执行。
7. 每条规则审计记录来源、类型、群、成员、消息、原因/置信度、模式、动作、协议、状态、耗时和错误中文说明。

## 9. AI 助手、知识库与业务应用

1. 验证普通聊天、普通问句、单独出现 DH 都静默；明确 `@DH`、`@ DH` 和真实提及元数据均触发回复。
2. 验证 AI Provider 模型列表、最小 Responses 请求、主备切换、401/403 配置异常、429/5xx 冷却、连接超时、总超时和敏感字段脱敏。
3. 测试自然回复、上下文 8 条上限、知识片段 3 条上限、FAQ LRU 缓存、缓存失效和同一消息 `ai_runs` 幂等。
4. 创建临时知识库与唯一事实文档，绑定指定群后提问；解除绑定并重复提问；最后删除临时资料。
5. 验证内置默认群规与 FAQ 为只读、未默认绑定、可复制为可编辑库；跨群知识绝不混入。
6. 验证 AI 人格、资料不足提示、公告优化、任务整理、每日摘要和人工接管。AI 聊天、AI 规则和人工群控保持隔离。
7. 验证预测应用启停、群权限、数据源健康、正常/缺期/乱序/过期、统计模板回退和回复字段隔离。未通过数据源验证时只显示状态，不生成候选结论。

## 10. 任务、摘要、计划与后台任务

1. 验证任务新建、编辑、负责人、创建人、截止、提醒、完成、取消、提醒记录和重启后持久 claim。
2. 验证每日摘要按电脑时区生成，只进入总览，不发送群聊；重复本地日期只生成一次。
3. 验证每日开群/关群、跨午夜、错过计划补齐、时区/DST、执行历史、群绑定冲突、手工状态保持到下一计划时间和失败退避。
4. 验证后台任务队列、暂停、恢复、失败重试、未知结果、退出最多等待 5 秒和重启后续跑。

## 11. 数据库、密钥、日志与恢复

1. 新建运行目录验证空库、schema 迁移、`quick_check`、迁移前快照、最近 3 份备份、损坏库恢复页面和原库保留。
2. 验证消息、动作、审计、计划、改名任务、任务提醒、摘要、知识块、AI run 的唯一约束和重启恢复。
3. 验证 DPAPI 密钥遮罩、日志/审计/崩溃报告/导出包不出现 API Key、Cookie、Token、Authorization、密码、完整真实消息或原始协议正文。
4. 生成脱敏诊断包，包含版本、哈希、配置摘要、进程/端口、错误、能力状态、审计摘要和日志索引；验证 ZIP 内无敏感数据。

## 12. UI、桌面体验与可访问性

1. 覆盖总览、群组与成员、消息台、机器规则、AI 控制规则、知识库、AI 助手、业务应用、任务与计划、审计、设置、调试。
2. 每页覆盖 loading、empty、ready、error、offline cached、权限不足、能力待人工验证、能力不可用和重试状态。
3. 验证所有按钮的中文悬停说明、加载状态、防重复点击、键盘焦点、标签、中文错误诊断和空数据文案。
4. 验证窗口最小尺寸、最大化、圆角、125%/150% DPI、窄宽度、表格水平滚动、模态窗口、日期选择、复选框、多选群与成员搜索。
5. 验证侧栏固定、版本信息、作者链接、托盘右键显示/暂停/退出、单击/双击恢复、Explorer 重启后图标恢复。

## 13. 性能、频率与长稳

1. 账号级写队列按顺序执行，间隔至少 500ms；读请求最多两个并发。
2. 记录队列等待、SQLite、规则、AI、协议、回读和总耗时。
3. 验证 UI 刷新、后台同步和手动刷新共享请求；高频操作不产生并发风暴。
4. 运行至少一次小型真实压力测试和一次 Fixture 1000 条突发测试，验证 `dropped=0`、数据库数量正确、群顺序正确、外部动作零重复。
5. 运行一段持续观察，覆盖登录完成、NIM 503、断线、页面重载、APP 重启、DH 重启、睡眠恢复和 AI 服务错误。
