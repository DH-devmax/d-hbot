# DH BOT 诊断与支持包

## 目的

DH BOT 的诊断包用于让使用者把异常信息交给维护人员排查，而不需要复制数据库、旺商聊目录或密钥。它只在使用者点击“调试 → 生成诊断包”时在本机生成，不会自动上传或发送。

## 使用方法

1. 复现问题后，尽量不要连续点击同一个操作。
2. 打开 `调试` 页面，点击 `生成诊断包`。
3. 复制显示的路径，在资源管理器中找到 `DH-BOT-support-YYYYMMDD-HHMMSS.zip`。
4. 将完整 ZIP、发生时间、操作步骤、群管理员状态和截图一起发送给维护人员。

不要删除或修改 ZIP 内的文件。维护人员可使用包内 `SHA256SUMS.txt` 对照 `manifest.json` 检查每个文件是否完整。

维护人员可在仓库根目录执行只读校验：

```sh
python3 tools/verify_support_bundle.py /path/to/DH-BOT-support-YYYYMMDD-HHMMSS.zip
```

校验工具不会解压或执行包内文件，会检查路径穿越、重复文件、必需清单、文件大小和 SHA-256；校验失败时不要把该包作为完整证据使用。

## 包内内容

| 文件 | 用途 | 隐私处理 |
|---|---|---|
| `diagnostic.json` | 版本、构建渠道、数据库完整性、连接和协议能力状态 | 账号、页面 URL 与敏感字段省略 |
| `audit-summary.json` | 最近最多 200 条审计的事件、级别与脱敏详情 | 账号、群、成员使用稳定别名；内容字段省略 |
| `logs/dh-*.jsonl` 或 `logs/dh-*.log` | 最近最多 20 个日志分段，每段最多 1 MiB | 密钥、会话、Cookie、密码、用户路径、内容和已知身份字段省略 |
| `SHA256SUMS.txt` | 包内文件的 SHA-256 | 不含外部数据 |
| `manifest.json` | 生成时间、文件名、大小与哈希 | 不含真实身份 |
| `README.txt` | 给维护人员的简短说明 | 不含外部数据 |

## 明确不包含

- `dh.db`、WAL、SHM 和数据库备份。
- `secrets.dat`、AI API Key、Webhook Token、Authorization、密码。
- 旺商聊 Cookie、Electron Profile、登录分区、Local Storage 或会话 Token。
- 原始消息正文、原始群公告、原始协议回包、Fixture 数据、源码、PDB 和 Source Map。
- 结构化的真实账号、群 ID、成员 ID；支持包使用 `ACCOUNT-001`、`GROUP-001`、`MEMBER-001` 这类稳定别名。

## 日志保留与完整性

本机日志路径为 `%APPDATA%\DH\3.0\logs`。新日志使用 JSONL，每条记录有本地时间、UTC 时间、会话 ID、递增序号、级别和脱敏文字。单个分段最大 8 MiB；系统最多保留 30 天和 64 MiB。运行中的程序每写入 256 条记录也会重新检查一次保留上限。

诊断包位于 `%APPDATA%\DH\3.0\support-bundles`。同一秒连续生成时会自动使用不同文件名，不会覆盖之前的包；最多保留 20 个、30 天和 128 MiB，超过上限会优先清理最旧的包。

错误和崩溃记录会调用磁盘刷新；支持包以临时文件写入并原子替换，防止得到半个 ZIP。生成完成后，界面显示 ZIP 自身 SHA-256；包内 `SHA256SUMS.txt` 校验所有诊断载荷文件，`manifest.json` 列出文件名、大小和对应哈希。

如果诊断包生成失败，请只发送生成失败的时间、调试页截图和 `%APPDATA%\DH\3.0\logs` 中最新文件的前后截图，不要发送数据库或 `secrets.dat`。维护人员也可以在收到截图后要求用户重新生成完整诊断包；不要让用户手动压缩整个 `%APPDATA%\DH` 目录。

维护代码或文档提交前还必须执行 `pnpm verify:docs`。该命令同时核对文档版本/schema/链接和仓库脱敏边界；支持包校验通过不等于源码仓库脱敏通过，两项检查不能互相替代。
